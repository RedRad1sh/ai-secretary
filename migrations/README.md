# Миграции схемы БД

Каталог для SQL-миграций, которые выполняются на деплое (шаг «миграции» в
`deploy/remote-deploy.sh`, запускается `scripts/migrate.py` **до** рестарта бота).

## Зачем

Схема бота создаётся сама (`bot/db.py`, `CREATE TABLE IF NOT EXISTS`) — этого
хватает для новых таблиц. Но когда нужно **изменить существующую** базу
(добавить колонку, индекс, перенести данные), рестарта недостаточно: нужен
одноразовый скрипт, который:

* применяется ровно один раз (учёт в таблице `schema_migrations`);
* не ломается при повторном запуске и на пустой базе;
* применяется ко всем базам: `data/bot.db` и `data/users/<ID>.db`.

## Как добавить миграцию

1. Создайте файл с числовым префиксом: `migrations/0002_add_reminder_channel.sql`
   (порядок применения — по имени файла, поэтому нумерация важна).
2. Пишите **идемпотентный** SQL: `CREATE INDEX IF NOT EXISTS`,
   `ALTER TABLE ... ADD COLUMN` (для колонок проверку существования SQLite не
   умеет — см. ниже), `UPDATE` без побочных эффектов.
3. Проверьте локально на копии базы:

   ```bash
   cp data/bot.db /tmp/probe.db
   .venv/bin/python scripts/migrate.py --data-dir /tmp/probe --dry-run   # план
   .venv/bin/python scripts/migrate.py --data-dir /tmp/probe             # прогон
   .venv/bin/python scripts/migrate.py --data-dir /tmp/probe             # «уже актуальна»
   ```

   Полный набор проверок — `python tests/test_migrations.py`.
4. Закоммитьте файл вместе с изменением кода, которое от него зависит.
   Деплой применит миграцию автоматически.

## Правила

* **Только вперёд.** Откат деплоя (`ROLLBACK_ON_FAILURE`) возвращает код, но не
  схему — поэтому миграции пишутся совместимыми со старой версией кода:
  добавляем колонки/таблицы, а не удаляем и не переименовываем в том же релизе.
* **SQLite не умеет `ADD COLUMN IF NOT EXISTS`.** Чтобы миграция не упала при
  повторной попытке, ветвите в `scripts/migrate.py` или сначала проверьте
  `PRAGMA table_info(<таблица>)`.
* **Бэкап перед рискованными изменениями**: `python scripts/backup.py /secure/backups`
  (SQLite backup API, все пользовательские базы + ключ шифрования).
* Тяжёлые миграции (пересборка таблицы) запускайте при остановленном боте —
  деплой специально останавливает сервис перед этим шагом.
