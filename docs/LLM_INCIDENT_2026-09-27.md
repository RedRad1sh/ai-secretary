## Найденные дефекты и изменения

| Раньше | Теперь |
|---|---|
| Общего таймаута цепочки нет | `LLM_TOTAL_TIMEOUT=35` для OpenAI-compatible chat, включая ожидание лимитера |
| 1024 → 2048, изменённый бюджет переходил на следующие модели | 4096 → максимум 8192 по умолчанию, бюджет каждого fallback независим |
| Пустой content проверялся до `length` | Сначала обрыв; повтор без JSON не тратится на заведомо обрезанный ответ |
| JSON отключался сразу у всех моделей | Кэш неподдержки отдельно для каждой модели |
| Не все внутренние ретраи учитывались лимитером | Любой физический chat-запрос проходит лимитер |
| Ошибка JSON-mode распознавалась только по `response_format` | Учитывается также явное сообщение о неподдержке JSON/feature |
| Два времени могли трактоваться как два события | Диапазоны не режутся; убрана замена AI-ответа только по количеству времён |
| Локальный разбор не показывал свою ограниченность | Предупреждение в карточке с просьбой проверить даты/повторы |
| Многособытийный ответ без даты дополнялся датой из всего сообщения | Дата остаётся для уточнения, не заимствуется из другого события |
| Повторы пропускали старт; после 8 напоминаний прекращались | Первое подходящее вхождение + пополнение горизонта |
| Напоминание помечалось sent даже после ошибки отправки | Только после успешного send |

Больший лимит токенов не гарантирует успех и может увеличить стоимость на платной
модели; общий таймаут ограничивает задержку, но не отменяет уже начатую тарификацию
на стороне провайдера. Платный whitelist сам по себе не является квотой расходов.
Новые лимиты относятся к OpenAI-compatible клиенту, не к нативному GigaChat/STT.

Офлайн-парсер намеренно ограничен: не восстанавливает сложный смысл, исключения
повторов и все разновидности временных интервалов. Результаты надо подтверждать.
Для точного воспроизведения последнего запроса нужен его исходный текст.
